WITH invoice_nums AS (
  SELECT DISTINCT InvoiceNum
  FROM landing.kinetic.sales_sherrigmquery_allcompanies
  WHERE InvoiceNum >= 790340
),
gaps AS (
  SELECT
    InvoiceNum,
    LEAD(InvoiceNum) OVER (ORDER BY InvoiceNum) AS next_invoice
  FROM invoice_nums
)
SELECT EXPLODE(SEQUENCE(InvoiceNum + 1, next_invoice - 1)) AS missing_invoice_num
FROM gaps
WHERE next_invoice - InvoiceNum > 1
ORDER BY missing_invoice_num
;

-- Anti-join approach for performance comparison
WITH full_sequence AS (
  SELECT EXPLODE(SEQUENCE(790340, 796900)) AS invoice_num
),
actual_invoices AS (
  SELECT DISTINCT InvoiceNum
  FROM landing.kinetic.sales_sherrigmquery_allcompanies
  WHERE InvoiceNum >= 790340
)
SELECT f.invoice_num AS missing_invoice_num
FROM full_sequence f
LEFT JOIN actual_invoices a
  ON f.invoice_num = a.InvoiceNum
WHERE a.InvoiceNum IS NULL
ORDER BY missing_invoice_num
;

-- Both completed in under a second, so at this scale the performance difference is negligible. However, there's an important **correctness** difference: the anti-join returned **331 rows** versus the LEAD approach's **282 rows**. The extra 49 are invoice numbers 796852–796900 — numbers beyond the current max InvoiceNum (796851) that the anti-join reports as "missing" simply because they don't exist yet.

-- **Tradeoffs:**

-- * **LEAD + SEQUENCE** — self-adjusting; only finds gaps *between* existing values with no hardcoded bounds. Slightly more complex but always accurate.
-- * **Anti-join** — conceptually simpler, but requires maintaining the upper bound (796900 today is already stale if new invoices arrive). Also generates ~6,500 rows upfront for the join, versus only scanning the actual distinct values.

-- At larger scales (millions of invoice numbers), the anti-join would generate a much larger in-memory sequence and a correspondingly larger join, while the LEAD approach only touches rows that actually exist. For this dataset though, either works fine — the LEAD approach just wins on accuracy without needing a hardcoded range. I've left the anti-join as statement 8 for reference.
