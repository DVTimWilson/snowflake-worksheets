WITH
mart_inventory_stock_levels AS (
  SELECT 
      INVENTORY_ITEM_ID
    , DATE
    , QUANTITY
    , SITE
    , ENTITY
--  FROM uat.silver.bsat_combined_inventory_stock_levels
  FROM uat.gold_coreview.mart_inventory_stock_levels
  WHERE DATE IS NOT NULL
),

mart_inventory_transactions AS (
  SELECT 
      PARTNUM
    , TO_DATE(TRANDATE) AS TRANDATE
    , SITE
    , COMPANY
    , SUM(CASE WHEN TRANCLASS = 'R' THEN TRANQTY END) AS RECEIPT_QTY
    , SUM(CASE WHEN TRANCLASS = 'I' THEN TRANQTY * -1 END) AS ISSUE_QTY
    , SUM(CASE WHEN TRANCLASS = 'A' AND TRANTYPE != 'MFG-VAR' THEN TRANQTY END) AS ADJUSTMENT_QTY
--  FROM uat.silver.bsat_combined_inventory_transactions
  FROM uat.gold_coreview.mart_inventory_usage
  GROUP BY PARTNUM, TO_DATE(TRANDATE), SITE, COMPANY
)

SELECT 
  sO.DATE
, sO.INVENTORY_ITEM_ID
, ANY_VALUE(sO.QUANTITY) AS OPENING_STOCK
, ANY_VALUE(sC.QUANTITY) AS CLOSING_STOCK
, ANY_VALUE(sC.QUANTITY) - ANY_VALUE(sO.QUANTITY) AS STOCK_MOVEMENT
, COALESCE(SUM(t.RECEIPT_QTY), 0) AS RECEIPT
, COALESCE(SUM(t.ISSUE_QTY), 0) AS ISSUE
, COALESCE(SUM(t.ADJUSTMENT_QTY), 0) AS ADJUSTMENTS
, ANY_VALUE(sO.QUANTITY) + COALESCE(SUM(t.RECEIPT_QTY), 0) + COALESCE(SUM(t.ISSUE_QTY), 0) + COALESCE(SUM(t.ADJUSTMENT_QTY), 0) - ANY_VALUE(sC.QUANTITY) AS ADJUSTMENTSBALANCING
FROM (
  SELECT date_day
  FROM uat.silver.dim_calendar_usa
  WHERE date_day BETWEEN 
    (SELECT date_add(MIN(DATE), 1) FROM uat.silver.bsat_combined_inventory_stock_levels WHERE DATE IS NOT NULL)
    AND 
    (SELECT date_add(MAX(DATE), 1) FROM uat.silver.bsat_combined_inventory_stock_levels WHERE DATE IS NOT NULL)
) AS c

-- Opening stock
LEFT OUTER JOIN mart_inventory_stock_levels AS sO
ON c.date_day - 1 = sO.DATE

-- Closing stock
LEFT OUTER JOIN mart_inventory_stock_levels AS sC
ON c.date_day = sC.DATE
AND sO.INVENTORY_ITEM_ID = sC.INVENTORY_ITEM_ID

-- All inventory transactions (single scan, conditional aggregation)
LEFT OUTER JOIN mart_inventory_transactions AS t
ON sO.INVENTORY_ITEM_ID = t.PARTNUM
AND sO.DATE = t.TRANDATE
AND sO.SITE = t.SITE
AND sO.ENTITY = t.COMPANY

WHERE 1=1
-- AND sO.INVENTORY_ITEM_ID = 'L000036-04-89-1903'
-- AND sO.INVENTORY_ITEM_ID = '1009015-06-01-0400'
-- AND sO.INVENTORY_ITEM_ID = '1002529-04-01-1006'
-- AND sO.INVENTORY_ITEM_ID IN (SELECT DISTINCT PARTNUM FROM mart_inventory_transactions)
-- AND (sO.INVENTORY_ITEM_ID IS NULL OR sO.DATE IS NULL)
GROUP BY sO.DATE, sO.INVENTORY_ITEM_ID
ORDER BY sO.INVENTORY_ITEM_ID, sO.DATE
;

Yes, there are meaningful improvements — the biggest being **performance**, with some **readability** gains too.

**Key improvements worth making:**

1. **Consolidate the 3 transaction sub-queries into 1** — currently `mart_inventory_usage` is scanned and aggregated 3 separate times (Receipts, Issues, Adjustments), then joined 3 times. A single scan with conditional `SUM(CASE WHEN TRANCLASS = 'R' ...)` eliminates 2 redundant full scans and 2 joins. This is the biggest win.

2. **Prune CTE columns** — both CTEs select far more columns than are actually consumed. `mart_inventory_stock_levels` only needs `INVENTORY_ITEM_ID, DATE, QUANTITY, SITE, ENTITY`. `mart_inventory_usage` only needs `PARTNUM, TRANDATE, SITE, COMPANY, TRANQTY, TRANCLASS, TRANTYPE`. Fewer columns = less I/O and memory.

3. **Remove dead calculations** — `STOCK_MOVEMENT` (via LAG), `PREV_DATE`, and `date_day` are computed in the subquery but never used in the outer SELECT/GROUP BY.

4. **Bound the calendar join** — if `dim_calendar_usa` isn't filtered, every date in the calendar produces rows. Adding a date range (e.g., matching the stock-level date range) avoids a potentially huge intermediate result.

**Is it worth changing?** The transaction consolidation alone (point 1) should roughly halve the I/O and join work for that part of the query, so yes — especially if you plan to remove the single-item filter and run this across many items.
